SIGNAL FROM NOISE

Two months of a self-healing CI

Every red build woke an agent.
Most of them shouldn't have.

A short story told with five numbers about turning an agent that cried wolf into one people actually read.

SAME 10 FIXES

180 times the watchdog said "this is broken, fix it".

Twice a day it reads the latest run of four pipelines. Anything red goes to a coding agent with the logs, the run history and links to the device lab's evidence.

Only 10 of those became merged fixes.

And 8 of the 10 were merged exactly as the agent wrote them. The fixes were good. The problem was everything around them.

60 weren't failures at all.

The build passed and the tests passed. A shared compliance step, inherited from a platform template, hung on Mac agents and marked the run "partially succeeded". The agent read it, made no change, and abandoned the PR. Sixty times.

63 matched five exact fingerprints.

Device lab blocked the test. Lab framework error. That same compliance step hanging hard enough to kill the machine. The system linker segfaulting. A pool with no machines in it. The agent called every single one infrastructure.

47 are exactly what the agent is for.

Timeouts, outages, a flaky lab. They look like bugs until someone reads the evidence. Two of the ten real fixes hid behind errors that looked exactly like these.

So we taught the watchdog to look before it barks.

Partial successes are ignored. A run is skipped only when every failure matches a known fingerprint. Anything else, even one unknown line, still goes to the agent.

Replaying two months of history through the new rules: 57 agent jobs instead of 180, and not one merged fix lost.

A third of the work.
All of the fixes.

  • Noise is the real cost. An agent nobody reads fixes nothing.
  • Filter by exact fingerprint, never by vibe. "Looks like infra" is how real bugs hide.
  • Prove it on history. We replayed every past failure before shipping the filter.
  • Next: tag every agent PR at creation so this scoreboard runs itself.
