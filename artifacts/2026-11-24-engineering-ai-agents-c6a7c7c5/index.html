LECTURE 01   /   Wed Sep 23

Introduction — What Are Agentic Systems?

Slides Video

Who picks the next step: your code or the model? That distinction separates a workflow from an agent and gives you a place to start debugging when a capable model still produces a bad outcome.

Detailed summary

The opening coding example separates finishing faster from understanding more: the two outcomes can move in opposite directions. The lecture then takes an agent apart into reasoning, memory, tools and an environment that returns observations. Reflection can change the next attempt without updating model weights. At the system level, ask who controls the sequence of actions; at the human level, check whether those actions actually helped the person.

LECTURE 02   /   Mon Sep 28

LLMs for Builders

Slides Video

A long context window is a capacity limit, not a promise of recall. An agent builder has to decide what the model sees, how much time it can spend reasoning, and which outputs the program can actually parse.

Detailed summary

Starting with the distribution over the next token, the lecture connects decoding choices to the behavior a user sees. Attention lets earlier tokens contribute to the current prediction, but attending to long inputs has a cost. Inference splits into processing the prompt and generating tokens incrementally. An example near the end shows accuracy falling as distracting documents accumulate: selecting evidence can be a better intervention than increasing the token budget.

LECTURE 03   /   Wed Sep 30

Retrieval-Augmented Generation (RAG)

Slides Video

Retrieval gives the model evidence you can inspect. If an answer is wrong, check what was indexed and what was returned before rewriting the generation prompt.

Detailed summary

A worked segmentation example shows why overlapping chunks and heading-based sections can expose different evidence from the same page. BM25 is useful for exact terms; dense retrieval can find passages that express the same idea in different words. Hybrid search can merge ranks rather than adding incomparable raw scores. Retrieval need not be a one-shot step: a system can reject weak evidence, rewrite the question and search again.

60:52 · Why combine ranks rather than scores?

LECTURE 04   /   Mon Oct 5

Tool Use & Function Calling

Slides Video

A tool call is a chain of decisions: recognize when outside help is needed, select an operation, supply its arguments and use the result. A plausible answer alone doesn't tell you which decision failed.

Detailed summary

Invented citations and deteriorating arithmetic illustrate why fluent text is not a substitute for a source or a calculator. Toolformer turns tool use into a learning problem: try inserting calls and retain examples where seeing the result helps predict subsequent text. Larger API catalogs introduce a selection problem. The lecture then switches to interfaces: a protocol can advertise the operations a service supports, but a course system that can both list assignments and post grades still needs permissions.

42:22 · How a candidate call earns its place

Frameworks & Orchestration

Slides Video Code

DSPy and LangGraph answer different questions: what should a model call accomplish, and what happens next? They can be used together. An evaluation tells you whether either abstraction bought you anything.

Detailed summary

The DSPy demo specifies inputs and outputs, runs examples and scores predictions against expected results. LECTURE 06   /   Mon Oct 12

Agent Design Patterns & Scaffolds

Slides Video

Plan once when the steps are predictable; decide after each observation when they aren't. The scaffold determines both when the model gets to reconsider and which part of the history it can see.

Detailed summary

The lecture moves from fixed workflows, such as a generator receiving feedback from an evaluator, to systems that choose their own actions. ReAct can adapt after a tool returns; ReWOO plans calls ahead of time, avoiding a fresh reasoning step between each pair. Reflexion uses feedback from past attempts to inform another try. An event log separates what happened from what enters the next prompt, so older observations can be hidden or compressed without erasing the underlying history.

51:12 · Planning ahead versus reacting

LECTURE 07   /   Wed Oct 14

Agent Memory Architectures

Slides Video

Remembering isn't the same as appending everything to a prompt. Decide what to keep as an experience, fact or reusable skill, then decide when it deserves space in working memory.

Detailed summary

The context window is working memory. An interaction from last week is episodic memory; a fact distilled from it is semantic memory; a reusable procedure serves a different purpose again. Simply accumulating lessons in the system prompt can work in a short experiment but becomes unwieldy in a long-running agent. Tiered storage and retrieval move selected material back into view. Conflicting memories and disappointing benchmark results complicate the assumption that remembering more must improve performance.

40:58 · When appending lessons stops scaling

LECTURE 08   /   Mon Oct 19

Multi-Agent Systems

Slides Video

Parallel tool calls don't necessarily mean multiple agents. The useful dividing line is who controls the work. Once several agents make decisions, communication and ownership become part of correctness.

Detailed summary

Compare a coordinator assigning tasks with a swarm of peers sharing a message board. Both can distribute work, but they make different demands on how participants report progress and discover what others know. A shared board and the Agent2Agent protocol illustrate different communication mechanisms. In the failure analysis, an agent promising an edit is not evidence that the edit happened. Check the resulting state rather than treating a handoff message as completion.

73:26 · Promises versus completed work

LECTURE 09   /   Wed Oct 21

Optimization

Slides Video

Optimize for a behavior you can measure. A date extractor can be semantically right but unusable by a calendar; parseability belongs in the objective before you tune prompts or model weights.

Detailed summary

Prompt optimization can start by saving successful demonstrations, trying combinations and scoring them on development examples. A single average can hide candidates that solve different subsets of tasks. For weight updates, the evidence changes: a student can imitate a teacher's trajectory or learn from relative rewards across several attempts. A coding example uses the fraction of passing tests to distinguish partially successful attempts instead of treating every unfinished solution alike.

LECTURE 10   /   Mon Oct 26

Guest Lecture: Terminal-Bench

Slides Video

A benchmark score is only as good as its verifier. Terminal-Bench treats a task as something an agent must do in an environment, not an answer that merely sounds right.

Detailed summary

The guest lecture distinguishes the harness that runs a trial, the trajectory that records it and the verifier that judges the result. A verifier can accept an invalid outcome or reject a valid alternative; both errors distort the leaderboard. Running a known solution checks whether the task can pass at all. Reading actual trial histories answers a different question: did an agent fail at the intended challenge, or did the environment, instructions or grading logic fail it?

48:59 · Using a known solution to check a task

LECTURE 11   /   Wed Oct 28

What Data Do Agents Need?

Slides Video: Data Selection & Quality

A task can be valid without being useful for training right now. The recording linked here asks how to pick tasks an agent sometimes solves, then adjust that choice as it learns.

Detailed summary

First check whether the grader rewards what the request asks for. Then run the model several times on each valid task. For training that compares attempts, a mix of successes and failures gives a signal that eight identical rewards cannot. In a worked example, the instructor sets aside both mastered tasks and tasks the model never solves, trains on the middle group, then retries the hard tasks with the updated model. Demonstrations need a different check: a run that ends successfully may still contain wasted steps you would not want the model to imitate.

33:50 · When to retry the tasks you set aside

LECTURE 12   /   Mon Nov 2

Data Selection & Quality

Slides Video: Benchmark Design

The recording linked here asks what a higher benchmark score actually proves. Two agents given the same request may face different tests if one gets more time, different tools or a changing website.

Detailed summary

A question with a fixed answer is relatively easy to rerun. A shopping agent evaluated on a live site might see different products on its second attempt. A simulated store makes comparisons repeatable, but its designer must decide which parts of real shopping to keep. The same issue applies to time limits: if a training job sits in a queue, charging the wait to the agent measures infrastructure as well as ability. Report those conditions alongside the score. As public tasks age, fresh examples can help distinguish solving a new problem from recalling an old solution.

42:01 · Live website or repeatable simulation?
